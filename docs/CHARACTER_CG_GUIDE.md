# 캐릭터 CG 제작 인계

기록일: 2026-09-18. 이 문서는 다음 세션에서 캐릭터 CG를 만들거나 수정할 때 읽는 프로젝트 지침이다.
파일 경로는 특별한 설명이 없으면 저장소 루트 기준이다. 숫자와 검증 결과는 기록 당시 상태이며,
작업을 재개할 때 실제 파일과 `js/portrait-catalog.js`를 다시 확인한다.

## 1. 작업 시작 순서

1. 현재 변경 사항을 확인하고 기존 작업을 보존한다. 이 문서를 읽었다는 이유만으로 이미지를 재생성하지 않는다.
2. 아래 표의 캐릭터 기준 PNG를 직접 열어 본다. 파일 이름이나 프롬프트만 읽고 그림을 추정하지 않는다.
3. 대상 대사 전후를 읽고 감정, 시선, 손동작, 소품, 등장 방향을 정한다.
4. 현재 세션의 이미지 생성 도구 지침을 확인하고, 아래 방식으로 한 이미지씩 만든다.
5. 결과를 프로젝트에 저장한 뒤 투명 합성과 실제 대본 전환을 검증한다.

## 3. 사용자가 정한 그림 규칙

### 그림체와 일관성

- 깨끗하고 가는 애니메이션 선, 매끄러운 셀 채색, 정리된 단색 면과 절제된 명암을 유지한다.
- 점묘, 거친 입자, 종이 질감, 붓 자국, 과한 광택이나 3D 느낌을 넣지 않는다.
- 과거에는 수정을 반복할수록 점묘 느낌이 심해졌다는 사용자 피드백이 있었다. **변형 A → A를 수정한 B → B를 수정한 C** 식으로 누적하지 말고, 각각 깨끗한 기준 원화에서 직접 만든다.
- 눈·입만 바꾸지 않는다. 같은 얼굴·의상을 유지하면서 고개, 시선, 어깨, 팔과 손의 동작을 장면에 맞게 바꾼다.
- 얼굴형, 머리 길이, 장식 위치, 날개 구조, 신체 비율이 변하지 않았는지 기준 원화와 나란히 비교한다.
- 중복 표정은 줄일 수 있지만, 감정의 강도나 대본상 역할이 다른 CG를 합치지 않는다. 특히 **일상적인 경고와 추방의 격노는 별개**다.

### 레밀리아의 의상과 뒷모습

- **발목까지 내려오는 긴 연분홍 드레스**다. 붉은 허리 리본, 밑단 가까이의 붉은 띠, 겹 프릴, 작은 붉은 구두를 유지한다.
- 전신에 짧은 치마, 드러난 무릎·허벅지, 슬릿을 넣지 않는다.
- 전신은 양쪽 날개 끝, 손끝, 치맛자락, 구두까지 프레임 안에 넣는다. 근접 표정 컷의 의도적인 상반신 구도와 전신의 잘림을 혼동하지 않는다.
- 첫 등장 뒷모습은 결투 상대라고 오해하고 자신을 홍마관의 주인으로 소개하는 장면이다. 허리와 어깨를 세우고, 당당히 돌아보거나 상대를 부르는 자세여야 한다.
- `back-regal`은 위엄 있는 등장, `back-flustered`는 체면을 지키려는 당황·헛기침, `back-reflective`는 회상이다. 세 역할을 하나로 합치지 않는다.

### 추방 전용 CG 4장

| 캐릭터 | 근접 분노 표정 | 위압감 있는 전신 |
| --- | --- | --- |
| 레밀리아 | `assets/레밀리아_new/cg-v2/furious.png` | `assets/레밀리아_new/cg-v2/fury-full.png` |
| 사쿠야 | `assets/사쿠야_new/cg-v2/furious.png` | `assets/사쿠야_new/cg-v2/fury-full.png` |

- 평범한 불만이나 귀여운 삐짐이 아니다. 내려간 눈썹, 좁고 날카로운 시선, 눈가의 짙은 그림자와 긴장된 입·자세로 강한 분노와 압박감을 표현한다.
- 레밀리아는 손님을 내쫓으며 문을 가리키는 격노, 사쿠야는 주인을 모욕한 손님을 가로막는 차갑게 억제된 분노다.
- 예전 `assets/레밀리아_new/매우화남2.webp`, `assets/사쿠야_new/냉정.webp`는 **감정 강도 참고만**으로 사용했다. 얼굴·옷·채색의 기준은 새 마스터다.
- 전신은 대화창 뒤에 발이 감춰지는 일반 스프라이트 배치와 구분한다. 현재 전용 프레임은 대화창 위에 몸 전체가 들어가도록 설정되어 있다.

### 레이무

- 기존 CG를 강하게 참고한 첫 시안은 사용자가 새로 그린 느낌이 부족하다고 지적하여 제외했다. **현재 새 기준 원화에서 이어서 작업한다.**
- 후일담에서 툇마루에 앉아 있으므로 앉은 구도를 유지한다.
- 기본, 매듭끈을 살피는 생각, 눈을 감고 생각, 생각을 멈춤, 턱을 괸 지루함, 손바닥을 펴며 한숨: 총 6종이다.
- 눈을 감은 생각과 한숨은 손·입·어깨 동작까지 다르게 만든다. 큰 머리 리본과 손끝을 실수로 자르지 않는다.

## 4. 실제 생성 절차

이 세트는 내장 `image_gen`으로 제작했다. 이 기록만으로 다른 API나 외부 서비스를 설정할 필요는 없다.
해당 세션 도구의 최신 사용 지침을 따르며, 도구가 없으면 사용 가능 여부를 먼저 확인한다.

1. 캐릭터 마스터 PNG와 필요한 감정·구도 참고만 선택한다. 로컬 이미지는 먼저 열어 확인한다.
2. 각 입력의 역할을 프롬프트에 구분한다: **얼굴·옷·그림체 기준**, **감정만 참고**, **새 캐릭터를 위한 그림체만 참고**.
3. 바꿀 요소와 고정할 요소를 명시한다. 기존 대본을 참고하여 손동작과 소품을 정한다.
4. 표정/동작/구도가 다른 이미지는 각각 별도로 생성한다. 여러 장짜리 시트 한 장을 결과물 여러 장으로 간주하지 않는다.
5. 배경은 실제 투명 RGBA PNG로 요청한다. 배경색·체커무늬를 그림 안에 그리지 않게 한다. 캐릭터 내부는 불투명하게 유지한다.
6. 결과를 확인하고 보정이 필요하면 기준 원화로 돌아가 문제 한 가지를 명확히 수정한다. 반복 보정으로 선과 질감이 악화되면 누적본을 계속 쓰지 않는다.
7. 선택한 결과를 `assets/<캐릭터 폴더>/cg-v2/<이름>.png`에 복사한다. 도구의 전역 생성 폴더 경로만 게임에 연결하지 않는다.
8. 같은 이름의 `<이름>.prompt.json`에 실제 사용한 프롬프트와 참조를 남긴다.

도구가 반환한 해상도는 요청한 숫자와 다를 수 있다. 현재 정사각형 결과는 주로 1254×1254,
세로형은 1024×1536이다. 임의로 강제 확대하거나 얼굴을 늘이지 말고, 결과의 실제 비율을 확인해 표시한다.

### 기존 캐릭터 변형용 프롬프트 틀

아래는 틀이다. 그대로 재사용하기 전에 캐릭터·장면·구도를 구체화하고 기존 `*.prompt.json`을 참고한다.

```text
Use case: identity-preserve. ONE visual-novel character sprite.
Input 1 is the current character master for exact face, hair, costume and clean anime style.
Input 2, if present, is ONLY an expression or pose reference; do not copy its old rendering.
Scene context: [actual dialogue and emotional situation].
Change: [specific eyes, brows, mouth, head direction, shoulder and hand gesture].
Keep: [character-specific face shape, hair, eyes, clothing, ornaments, proportions and wings].
Framing: [close portrait OR full body]; [entire bow/wings/hands/hem/shoes where required] inside margins.
Clean fine linework, smooth controlled cel shading, no stippling, grain, painted texture or 3D gloss.
Genuine transparent RGBA background, opaque character interior, clean alpha edges.
No scenery, drawn checkerboard, aura, text, watermark or unrequested props.
```

새 캐릭터 제작 시에는 `Create a brand-new character master. Supplied images are STYLE references only, not edit targets or the character's identity.`처럼 역할을 명확히 하고,
새 캐릭터의 얼굴·머리·옷·포즈를 따로 설명한다. 레이무의 `neutral.prompt.json`에 이 방식의 실제 프롬프트가 있다.

### 생성 기록 형식

```json
{
  "generator": "built-in image_gen",
  "id": "character/variant",
  "refs": ["assets/캐릭터/cg-v2/neutral.png"],
  "prompt": "실제 도구에 전달한 전체 프롬프트",
  "path": "assets/캐릭터/cg-v2/variant.png",
  "source": "도구가 반환한 원본 경로"
}
```

기존 기록의 `refs`에는 절대 경로와 상대 경로가 섞여 있다. 다른 컴퓨터에서는 저장소 안의 해당 파일로 해석한다.
`source`의 전역 생성 폴더는 제작 이력일 뿐, 다음 세션에서 반드시 있어야 하는 파일이 아니다.
앞으로의 참조 기록은 가능한 한 프로젝트 상대 경로로 남긴다. 같은 프롬프트도 완전히 동일한 픽셀 출력을 보장하지 않는다.

뒤쪽 대본 파일이 앞쪽 노드의 표현을 덮어쓸 수 있다. 첫 번째 검색 결과만 보지 말고 `index.html`의 로드 순서와 최종 `VN_STORY.nodes`를 확인한다.
추방 CG 최종 연결은 `js/story/18-expulsion-cg.js`에서 한다. 대사를 새로 쓰는 작업이 아니라면 기존 문장·노드 ID·분기·저장 버전을 유지한다.

| 파일 | 역할 |
| --- | --- |
| `js/portrait-catalog.js` | 실제 PNG, 캐릭터, 표시 이름, 기존 표정 별칭, 프레임의 기준 목록 |
| `js/assets.js` | 카탈로그에서 이미지 경로·표정 정보·갤러리 대표 키 생성 |

| `js/game.js` | 이미지 전환과 `data-frame` 적용, 실제 이미지가 같으면 불필요한 재전환 방지 |
| `css/character-cg.css` | 기본 비율, 날개, 모바일 배치 |
| `css/expulsion-cg.css` | 분노 근접과 전신 전용 배치 |
| `css/epilogue.css` | 신사 배경의 레이무 위치; 새 CG 모바일 규칙과 함께 확인 |

프레임은 `gown`(레밀리아 기본 전신), `standing`(세로형 CG; 레이무는 이 프레임이지만 실제 포즈는 앉음),
`full`(파츄리 독서 전신), `confrontation`(분노 근접), `intimidation-wide`(레밀리아 추방 전신),
`intimidation-tall`(사쿠야 추방 전신)을 사용한다.

2026-09-18 기준 실제 CG는 **32장**: 레밀리아 14, 사쿠야 8, 파츄리 4, 레이무 6이다.
기존 55개 표정 키를 보존하고 3개를 추가하여 총 58개 별칭이며, 대본 노드는 840개다.
파츄리 `master-reading.png`는 보조 원본이므로 실제 32장에 포함하지 않는다.

## 6. 투명화와 실제 화면 검증

원본 뷰어가 완전히 투명한 픽셀의 RGB까지 보여 주면 색 띠나 후광이 보일 수 있다.
이는 곧바로 투명화 실패를 뜻하지 않지만, 반대로 자동으로 무시해서도 안 된다.
**알파 값과 브라우저 합성 결과를 함께 확인한다.**

1. PNG가 RGBA이고 알파 0인 배경 픽셀이 실제로 존재하는지 확인한다.
2. 캐릭터 내부에는 거의 불투명한 픽셀이 충분히 있는지 확인한다. 일부 정상 생성본의 최대 알파는 254다. 255가 아니라는 이유만으로 재처리하지 않는다.
3. 밝은색·어두운색·체커 배경에서 가장자리, 날개 막, 머리카락·리본 사이의 투명 부분, 눈·옷 내부의 구멍 여부를 직접 본다.
4. PNG를 JPG/RGB로 저장하거나 흰색을 일괄 삭제하여 의상까지 투명해지게 하지 않는다. 그림 보정·배경 제거도 현재 이미지 도구 지침에 맞게 처리한다.
5. 게임에서 실제 대사를 복원하거나 진행하여 로딩 성공, 얼굴·날개·손·전신의 표시, 앞뒤 장면 전환을 확인한다.

비교 페이지: `assets/레밀리아_new/cg-v2/review.html`.
`?view=expulsion`은 추방 4장, `?view=레이무`는 새 레이무 6장을 보여 준다. 배경색을 바꾸고 이미지를 눌러 확대할 수 있다.
다른 폴더 이름을 추정하지 말고 카탈로그를 사용한다.

로컬 HTTP 서버가 없다면 저장소 루트에서 다음처럼 실행할 수 있다. 포트가 사용 중이면 기존 서버인지 확인하거나 다른 포트를 사용한다.

```powershell
python -m http.server 8768 --bind 127.0.0.1
```

현재 세션의 브라우저 도구로 `http://127.0.0.1:8768/`를 연다. 이전 세션의 서버·브라우저·세션 ID가 계속 살아 있다고 가정하지 않는다.
원본 파일을 교체한 뒤에는 캐시 때문에 예전 그림이 보일 수 있으므로 새 브라우저 컨텍스트 또는 캐시 갱신 후 실제 이미지 경로·크기를 확인한다.

### 완료 전에 확인할 항목

- 요청된 최종 PNG가 전부 프로젝트 안에 있고 각 파일 옆에 정확한 프롬프트 기록이 있다.
- 실제 대본에서 쓰는 모든 표정 키가 존재하며 경로에 확장자가 포함되어 있다. 과거처럼 무조건 `.webp`를 덧붙이지 않는다.
- 갤러리와 미리 불러오기가 동일 이미지 별칭을 중복 계산하지 않는다.
- `VN_PRELOAD.run(() => {})`의 `failures`가 비어 있는지 로딩 완료 후 확인한다. 2026-09-18 검증에서는 총 50개 자산이 성공했다.
- 데스크톱 1440×900, 모바일 390×844에서 확인한다. 전신 CG는 구두까지 대화창 위에 있어야 하고, 레이무의 리본·팔이 좌우에서 잘리지 않아야 한다.
- 추방 연출을 바꿨다면 `mistaken-memory-8`부터 실제로 넘겨 “닫힌 문 너머” 결말까지 도달하는지 확인한다.
- 레이무 확인 위치 예: `reimu-home-1`, `-2`, `-6`, `-11`, `-14`, `-18`.
- 변경한 JS의 구문 검사와 `git diff --check`를 실행한다. 문서만 바꾼 경우 이미지 생성이나 게임 전체 재검사는 필요하지 않다.

당시 스크린샷과 점검 스크립트는 로컬 `output/playwright/`에 있다. 이 폴더는 Git 제외 대상이므로 다른 체크아웃에는 없을 수 있다.
증거가 없을 때 과거 검증을 현재 검증으로 말하지 않는다. 위 절차로 새로 확인하면 된다.

## 7. 기록을 갱신할 때

- 각 PNG 옆 `*.prompt.json`: 그 이미지의 실제 프롬프트와 참조.
- 이 문서: 앞으로 작업할 사람이 사용할 현재 기준과 절차.
- `assets/레밀리아_new/cg-v2/GENERATION.md`: 장면 선택 근거와 제작 당시 검증 기록.
- `AGENTS.md`와 README: 이 문서를 찾는 진입점.

인계 문서와 진입점은 `.gitignore`의 허용 목록에 포함되어 있다. 아직 커밋·푸시되지 않은 파일은 다른 체크아웃에 자동 전달되지 않으므로,
새 세션은 실제 파일과 Git 상태부터 확인한다. 이 기록 자체는 커밋·배포를 수행했다는 뜻이 아니다.
